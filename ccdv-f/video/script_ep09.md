## SLIDE: 押さえどころ（2）ヘッドレス・セッション・自動モード
| 項目 | 押さえどころ（公式ドキュメント） |
| ヘッドレスモード | claude -p "..."。--output-format json（または stream-json）、--allowedTools、--continue、--bare（自動検出をスキップ。スクリプトや CI に推奨） |
| セッション管理 | --continue、--resume、/clear |
| 自動モード（auto mode） | 詳細は要確認（公式の permissions のページで確認） |
- 注意：-p で **--bare を付けない** と、信頼していないフォルダでもプロジェクトのフックや .mcp.json が動く（公式に明記）

めたん: ヘッドレスモード、というのは？
ずんだもん: 対話せずに、{claude -p|クロード ハイフン ピー}で実行するのだ。スクリプトや{CI|シーアイ}で使うのだ。
めたん: 結果を、プログラムで受け取りたいときは？
ずんだもん: {--output-format json|アウトプットフォーマット ジェイソン}か、{stream-json|ストリーム ジェイソン}なのだ。使えるツールは、{--allowedTools|アラウドツールズ}で指定するのだ。
めたん: {--bare|ベア}というのは？
ずんだもん: 自動検出をスキップするオプションなのだ。スクリプトや{CI|シーアイ}に推奨なのだ。
ずんだもん: 注意点があるのだ。{-p|ハイフン ピー}で{--bare|ベア}を付けないと、信頼していないフォルダでも、プロジェクトのフックや{.mcp.json|ドット エムシーピー ジェイソン}が動いてしまうのだ。
めたん: それは危ないですわね。セッション管理は？
ずんだもん: {--continue|コンティニュー}、{--resume|レジューム}、{/clear|スラッシュ クリア}なのだ。自動モードの詳細は、要確認なのだ。

## SLIDE: 8-1 エラーコード一覧（1/2）
| HTTP | type | 対処 |
| 400 | invalid_request_error | リクエストを直す（リトライしても無駄）。設定した支出上限に達したときも400 |
| 401 | authentication_error | キーを確認する |
| 403 | permission_error | 権限を確認する |
| 404 | not_found_error | パスやIDを確認する |
| 413 | request_too_large | サイズを減らす（Messages API は128MB、Batch は256MB） |

めたん: 後半は、分野4のデバッグとエラー処理ですわ。
ずんだもん: まず、エラーコードの表なのだ。400は{invalid_request_error|インバリッドリクエストエラー}。リクエストを直すのだ。
めたん: リトライすれば、通ることは？
ずんだもん: 無駄なのだ。400は、直すのだ。それと、設定した支出上限に達したときも400になるのだ。
めたん: 401と403は、前回やりましたわね。
ずんだもん: 401はキー、403は権限を確認するのだ。404は{not_found_error|ノットファウンドエラー}で、パスや{ID|アイディー}を確認するのだ。
めたん: 413は？
ずんだもん: {request_too_large|リクエスト トゥーラージ}なのだ。サイズを減らすのだ。{Messages API|メッセージズ エーピーアイ}は128メガバイト、バッチは256メガバイトまでなのだ。

## SLIDE: 8-1 エラーコード一覧（2/2）
| HTTP | type | 対処 |
| 429 | rate_limit_error | バックオフし、retry-after に従う（ティアの支出上限による429には retry-after がない） |
| 500 | api_error | 指数バックオフでリトライ。続くなら request_id を添えて問い合わせる |
| 504 | timeout_error | ストリーミングを使う |
| 529 | overloaded_error | 一時的な過負荷。バックオフしてリトライ |

めたん: 429は、第2回で出てきましたわね。
ずんだもん: {rate_limit_error|レートリミットエラー}なのだ。バックオフして、{retry-after|リトライアフター}に従うのだ。
ずんだもん: ただし、ティアの支出上限による429には、{retry-after|リトライアフター}がないのだ。
めたん: 500は？
ずんだもん: {api_error|エーピーアイエラー}なのだ。指数バックオフでリトライして、続くなら{request_id|リクエストアイディー}を添えて問い合わせるのだ。
めたん: 504は、第1回でやりましたわ。ストリーミング、ですわね。
ずんだもん: その通りなのだ。そして529は{overloaded_error|オーバーローデッドエラー}。一時的な過負荷だから、バックオフしてリトライなのだ。

## SLIDE: 切り分けと評価（eval）
- **切り分け**：HTTP エラーや例外 → **統合レイヤーの問題**
- 200 で返った内容の誤り → **モデル出力（プロンプトやコンテキスト）の問題**
- **トレース**（入力・ツール呼び出し・出力のログ）で、どこで失敗したかを特定する
- **評価（eval）**：「完了」の定義をテストで作る
- 回帰を検出し、**スキーマ検証とルーブリック採点を併用** する

めたん: うまく動かないとき、どこから調べればよろしいの？
ずんだもん: 切り分けなのだ。{HTTP|エイチティーティーピー}エラーや例外なら、統合レイヤーの問題なのだ。
めたん: 200で返ってきたのに、内容が間違っていたら？
ずんだもん: モデル出力の問題なのだ。プロンプトやコンテキストを見直すのだ。
めたん: どこで失敗したか、どう特定しますの？
ずんだもん: トレースなのだ。入力、ツール呼び出し、出力のログで、特定するのだ。
めたん: 評価、{eval|イーバル}についても教えてくださる？
ずんだもん: 「完了」の定義を、テストで作るのだ。回帰を検出して、スキーマ検証とルーブリック採点を、併用するのだ。
