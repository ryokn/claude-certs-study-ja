## SLIDE: コンテンツの境界とスキーマ設計
- **コンテンツの境界**：信頼できる指示 と 信頼できないデータ を分ける
- 信頼できないデータ＝ユーザーの文書、Webページ、ツールの結果
- XML タグなどで区切る
- **スキーマ設計**：input_schema や構造化出力のスキーマは **最小限**
- 必須項目・列挙型（enum）・**additionalProperties: false** を使う
- 説明を明確に書く

めたん: 次は、コンテンツの境界ですわね。
ずんだもん: 信頼できる指示と、信頼できないデータを分ける、という考え方なのだ。
めたん: 信頼できないデータ、とは？
ずんだもん: ユーザーの文書、ウェブページ、ツールの結果なのだ。これを、{XML|エックスエムエル}タグなどで区切るのだ。
めたん: 指示とデータが混ざらないように、ですわね。
ずんだもん: そうなのだ。続いてスキーマ設計。ツールの{input_schema|インプットスキーマ}や、構造化出力のスキーマは、最小限にするのだ。
めたん: 何を使えばよろしいの？
ずんだもん: 必須項目、列挙型の{enum|イーナム}、それに{additionalProperties|アディショナルプロパティーズ} {false|フォルス}なのだ。そして説明を、明確に書くのだ。

## SLIDE: セッションハイジーンとプラグイン管理
- **セッションハイジーン**：無関係なタスクは **新しいセッション** で（Claude Code なら /clear など）
- 長いセッションでは古い文脈が **ドリフト** の原因になる
- 続ける場合は **要約して引き継ぐ**
- **プラグイン**：スキル、エージェント、フック、MCP サーバーをまとめて配布する単位
- 依存関係とバージョンを管理する

めたん: 同じセッションで続けると、何がいけませんの？
ずんだもん: 長いセッションでは、古い文脈が、ドリフトの原因になるのだ。
めたん: どうしても続けたいときは？
ずんだもん: 要約して、引き継ぐのだ。
めたん: プラグインというのは？
ずんだもん: スキル、エージェント、フック、{MCP|エムシーピー}サーバーを、まとめて配布する単位なのだ。依存関係とバージョンを、管理するのだ。

## SLIDE: 1-3　ソフトウェアエンジニアリングの基礎（7.4%）★

## SLIDE: JSON・バージョン管理・リファクタリング
- **JSON**：LLM の出力は **必ず検証してからパース**（防御的なパース）
- **バージョン管理と SDLC**：プロンプト、CLAUDE.md、.claude/settings.json は **コードと一緒にレビュー**
- **CI で eval を回す**
- **大規模なリファクタリング**：小さな単位に分け、**テストで守りながら** 進める
- Claude Code なら **プランを立ててから実行し、差分をレビュー**

ずんだもん: 次は{JSON|ジェイソン}。{LLM|エルエルエム}の出力は、必ず検証してからパースするのだ。防御的なパースなのだ。

めたん: プロンプトも、コードと同じ扱いですのね。
ずんだもん: その通りなのだ。そして、{CI|シーアイ}で{eval|イーバル}を回すのだ。

## SLIDE: コード例：同時実行数を制限して自動リトライ
```
import Anthropic from "@anthropic-ai/sdk";
const client = new Anthropic({ maxRetries: 4 }); // 既定は2回
async function runAll(items: string[], limit = 5) {
  const results: string[] = []; let i = 0;
  const worker = async () => { while (i < items.length) { const idx = i++;
    const r = await client.messages.create({ model: "claude-haiku-5-5", max_tokens: 200,
      messages: [{ role: "user", content: items[idx] }] });
    results[idx] = r.content[0].type === "text" ? r.content[0].text : ""; } };
  await Promise.all(Array.from({ length: limit }, worker));
  return results;
}
```

めたん: コード例もありますわね。
ずんだもん: {TypeScript|タイプスクリプト}の例なのだ。ワーカーを5個だけ動かして、同時実行数を制限しているのだ。
めたん: {maxRetries|マックスリトライズ} 4、というのは？
ずんだもん: {SDK|エスディーケー}の自動リトライの回数なのだ。既定は2回で、ここでは4回に増やしているのだ。
めたん: 自前でリトライを書かなくても、{SDK|エスディーケー}がやってくれますのね。
ずんだもん: そうなのだ。詳しくは、分野5の回でもう一度出てくるのだ。
