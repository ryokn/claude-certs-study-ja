## SLIDE: 6-1 プロンプトインジェクション対策 ★
- 特に注意：**間接型**（Webページ・メール・ツールの結果などに仕込まれる）
- 対策：**信頼できない入力として扱い、指示と分離する**
- ツールは **最小権限** にする
- 機密性の高いアクションには **フックや人間の承認** を挟む

めたん: プロンプトインジェクション、というのは？
ずんだもん: 悪意のある指示を紛れ込ませて、モデルを操ろうとする攻撃なのだ。特に注意なのが、間接型なのだ。
めたん: 間接型？
ずんだもん: ウェブページ、メール、ツールの結果などに、指示が仕込まれるのだ。ユーザーが直接打ち込むわけではないのだ。
めたん: 怖いですわ。どう防ぎますの？
ずんだもん: まず、信頼できない入力として扱って、指示と分離するのだ。
ずんだもん: 次に、ツールは最小権限にするのだ。そして、機密性の高いアクションには、フックや人間の承認を挟むのだ。

## SLIDE: 効かない対策と PII（公式サンプル問題2）
- サンプル問題2：Web ページの隠し指示 → **信頼できない入力として分離し、ガードレールやフックで機密性の高いアクションを防ぐ**
- 効かない対策：
- **temperature を上げる**
- **「悪意ある指示に従わないで」とお願いする**
- **大きなモデルに変える**（指示に忠実なモデルほど、かえって影響を受けやすいことがある）
- PII：**最小化、マスキング、ログに残さない、データ保持ポリシー**

めたん: 公式のサンプル問題にも、ありましたわね。
ずんだもん: サンプル問題2なのだ。ウェブページの隠し指示が題材で、答えは、信頼できない入力として分離して、ガードレールやフックで、機密性の高いアクションを防ぐ、なのだ。
めたん: 逆に、効かない対策は？
ずんだもん: 3つあるのだ。{temperature|テンパラチャー}を上げる。「悪意ある指示に従わないで」とお願いする。大きなモデルに変える。
めたん: 大きなモデルなら、賢く見抜いてくれそうですけれど？
ずんだもん: 指示に忠実なモデルほど、かえって影響を受けやすいことがあるのだ。
めたん: 個人情報の扱いは？
ずんだもん: {PII|ピーアイアイ}は、最小化、マスキング、ログに残さない、それにデータ保持ポリシーなのだ。

## SLIDE: 6-2 ガードレールと安全なデプロイ（2.3%）
- ガードレールの **多層化**：
- **入力のスクリーニング** → **権限の制御** → **出力の検証** → **監視**
- **セキュアバイデザイン**：プライバシー、IAM、最小権限

めたん: ガードレールは、1つあれば十分ですの？
ずんだもん: 多層化するのだ。入力のスクリーニング、権限の制御、出力の検証、そして監視なのだ。
めたん: 4段構えですわね。
ずんだもん: そうなのだ。それと、セキュアバイデザイン。最初から、プライバシー、{IAM|アイエーエム}、最小権限を組み込んでおくのだ。

## SLIDE: 6-3 Claude のフック（1.0%）★
- Claude Code の主なイベント：
- **SessionStart**、**UserPromptSubmit**、**PreToolUse**（実行前。ブロックできる）、**PermissionRequest**
- **PostToolUse**、**PostToolUseFailure**、**Notification**、**SubagentStop**、**Stop**、**PreCompact**、**SessionEnd** など
- **終了コード2 ＝ ブロッキングエラー**（PreToolUse ならツール呼び出しを阻止）
- JSON の **permissionDecision: "deny"** でも拒否できる
- **終了コード0のときの stderr は Claude には見えない**

めたん: 第5回でも出てきた、フックですわね。
ずんだもん: {Claude Code|クロードコード}には、いろいろなイベントのフックがあるのだ。
ずんだもん: {SessionStart|セッションスタート}、{UserPromptSubmit|ユーザープロンプトサブミット}、{PreToolUse|プレツールユース}、{PermissionRequest|パーミッションリクエスト}。
ずんだもん: {PostToolUse|ポストツールユース}、{PostToolUseFailure|ポストツールユースフェイリャー}、{Notification|ノーティフィケーション}、{SubagentStop|サブエージェントストップ}、{Stop|ストップ}、{PreCompact|プレコンパクト}、{SessionEnd|セッションエンド}などなのだ。
めたん: ツールを止められるのは？
ずんだもん: 実行前の{PreToolUse|プレツールユース}なのだ。ブロックできるのだ。
めたん: どうやって止めますの？
ずんだもん: 終了コード2なのだ。ブロッキングエラーになって、ツールの呼び出しを阻止するのだ。{JSON|ジェイソン}で{permissionDecision|パーミッションディシジョン} {deny|デナイ}を返しても、拒否できるのだ。
めたん: 終了コード0で、エラー出力にメッセージを書いたら？
ずんだもん: それが、ひっかけなのだ。終了コード0のときの標準エラー出力は、{Claude|クロード}には見えないのだ。

## SLIDE: フックの設定例（.claude/settings.json）
```
{ "permissions": { "deny": ["Read(./.env)"], "allow": ["Bash(npm test)"] },
  "hooks": { "PreToolUse": [ { "matcher": "Bash",
     "hooks": [ { "type": "command", "command": ".claude/hooks/block-rm.sh" } ] } ] } }
```
- **matcher: "Bash"** → Bash を実行する前に block-rm.sh を実行
- スクリプトが **終了コード2** で終われば、ツール呼び出しを **阻止**
- permissions の **deny / allow** と組み合わせて、確実に制御する

めたん: フックは、どこに書きますの？
ずんだもん: {settings.json|セッティングス ジェイソン}の{hooks|フックス}なのだ。第3回で見た例と、同じ形なのだ。
ずんだもん: {matcher|マッチャー}が{Bash|バッシュ}だから、{Bash|バッシュ}を実行する前に、このスクリプトが動くのだ。
めたん: スクリプトが終了コード2で終われば……
ずんだもん: ツールの呼び出しを、阻止できるのだ。パーミッションの{deny|デナイ}と{allow|アロウ}と組み合わせて、確実に制御するのだ。

## SLIDE: 6-4 ID、シークレット、キーの管理（1.6%）
- キーは **環境ごとに分ける**
- **シークレットマネージャーか環境変数** で注入する
- **コード、CLAUDE.md、ログ、フロントエンドには置かない**
- ローテーションと利用監視を行い、アクセス承認のレベルを確認する
- **401 authentication_error**：キーが不正・失効・期限切れ
- **403 permission_error**：そのリソースへの権限がない

めたん: {API|エーピーアイ}キーの扱いも、大事ですわね。
ずんだもん: キーは、環境ごとに分けるのだ。そして、シークレットマネージャーか環境変数で注入するのだ。
めたん: 置いてはいけない場所は？
ずんだもん: コード、{CLAUDE.md|クロード エムディー}、ログ、フロントエンドなのだ。
めたん: {CLAUDE.md|クロード エムディー}も、だめですのね。
ずんだもん: リポジトリにコミットされることもあるから、だめなのだ。それに、ローテーションと利用監視をして、アクセス承認のレベルも確認するのだ。
めたん: キーが間違っていると、どんなエラーになりますの？
ずんだもん: 401の{authentication_error|オーセンティケーションエラー}なのだ。キーが不正、失効、期限切れのときなのだ。
ずんだもん: 403の{permission_error|パーミッションエラー}は、そのリソースへの権限がないときなのだ。
