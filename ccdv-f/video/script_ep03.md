## SLIDE: settings.json の優先順位（上ほど強い）★
- ① **管理設定**（managed-settings.json、MDM、サーバー管理）：個人では上書きできない
- ② **コマンドライン**（--settings）
- ③ **プロジェクトローカル**（.claude/settings.local.json）：個人用。git には含めない
- ④ **共有プロジェクト**（.claude/settings.json）：チームでコミットする
- ⑤ **ユーザー**（~/.claude/settings.json）

## SLIDE: CLAUDE.md の種類
| 種類 | 場所 | 共有範囲 |
| 管理ポリシー | 例：Linux は /etc/claude-code/CLAUDE.md | 組織全体 |

| プロジェクト | ./CLAUDE.md または ./.claude/CLAUDE.md | チーム（コミットする） |

めたん: プロジェクト用は？
ずんだもん: リポジトリ直下の{CLAUDE.md|クロード エムディー}か、{.claude|ドットクロード}フォルダの中なのだ。チームでコミットするのだ。
めたん: 自分だけのメモを書きたいときは？
ずんだもん: {CLAUDE.local.md|クロード ローカル エムディー}なのだ。これは{.gitignore|ギットイグノア}に入れるのだ。

## SLIDE: インポートとモデルバージョンの固定
- **@path/to/file** で別ファイルを取り込める（インポートは **最大4階層**）
- CLAUDE.md は **1ファイル200行以内** が目安（公式の memory ページ）
- **モデルバージョンの固定**：モデルIDを設定ファイルで明示する
- リリース間で **互換性のない挙動変更** が起こりうる → **更新前に eval で確認**
- 4.6世代以降はモデルIDそのものが固定スナップショット（それ以前はエイリアスが日付付きIDを指していた：要確認）

めたん: {CLAUDE.md|クロード エムディー}が長くなってしまったら、どうしますの？
ずんだもん: アットマークとパスで、別のファイルを取り込めるのだ。インポートは、最大4階層までなのだ。
ずんだもん: それと、{CLAUDE.md|クロード エムディー}は、1ファイル200行以内が目安なのだ。
めたん: 短く保つのが大事ですのね。次は、モデルバージョンの固定ですわ。
ずんだもん: モデル{ID|アイディー}を、設定ファイルで明示するのだ。
めたん: なぜ固定しますの？
ずんだもん: モデルのリリース間で、互換性のない挙動変更が起こりうるからなのだ。だから、更新する前に{eval|イーバル}で確認するのだ。
めたん: 「モデルは常に最新を自動で使う」は……
ずんだもん: ひっかけなのだ。固定して、{eval|イーバル}で検証してから更新するのだ。
ずんだもん: ちなみに、4.6世代以降は、モデル{ID|アイディー}そのものが固定スナップショットなのだ。試験での扱いは、要確認なのだ。

## SLIDE: 構成管理のひっかけ ★
| ひっかけ | 正しくは |

## SLIDE: settings.json の例（チームで共有）
```
// .claude/settings.json（チームで共有）
{ "permissions": { "deny": ["Read(./.env)"], "allow": ["Bash(npm test)"] },
  "hooks": { "PreToolUse": [ { "matcher": "Bash",
     "hooks": [ { "type": "command", "command": ".claude/hooks/block-rm.sh" } ] } ] } }
```
- permissions：**deny** で .env の読み取りを禁止、**allow** で npm test を許可
- hooks：Bash の実行前（PreToolUse）にスクリプトでチェック
- settings ファイルは **厳密な JSON** → 実際にはコメントは書けない（上のコメントは説明用）

めたん: 実際の{settings.json|セッティングス ジェイソン}は、どんな形ですの？
ずんだもん: これは、チームで共有する{.claude/settings.json|ドットクロード セッティングス ジェイソン}の例なのだ。
ずんだもん: {permissions|パーミッションズ}の{deny|デナイ}で、{.env|ドットエンブ}ファイルの読み取りを禁止して、{allow|アロウ}で{npm test|エヌピーエム テスト}を許可しているのだ。
めたん: 下の{hooks|フックス}は？
ずんだもん: {Bash|バッシュ}を実行する前、つまり{PreToolUse|プレツールユース}で、スクリプトを動かしてチェックするのだ。
めたん: {CLAUDE.md|クロード エムディー}に「読まないで」と書くより、確実ですわね。
ずんだもん: その通りなのだ。これが、指示と強制の違いなのだ。
ずんだもん: ちなみに、{settings|セッティングス}ファイルは厳密な{JSON|ジェイソン}なのだ。だから、実際にはコメントは書けないのだ。
めたん: では、ここで問題ですわ。{settings.local.json|セッティングス ローカル ジェイソン}と、共有の{settings.json|セッティングス ジェイソン}。強いのは、どちら？
ずんだもん: ローカルの方なのだ。3番目と4番目だから、ローカルが上なのだ。
めたん: では、管理設定とコマンドラインでは？
ずんだもん: 管理設定なのだ。管理設定は、個人では上書きできない、いちばん強い設定なのだ。

## SLIDE: 1-5 要件の理解（3.4%）
- ビジネス要件を **機能要件**（何をするか）と **非機能・インフラ要件** に分ける
- 非機能要件：**レイテンシ、コスト、データ所在地、可用性、監査**
- 非機能要件に応じて **モデル**、**バッチかリアルタイムか**、**提供プラットフォーム** を選ぶ
- 要件は **評価可能な受け入れ基準** にしてから作る

めたん: それを分けて、どうしますの？
