## SLIDE: ワークフロー と エージェント ★
| | ワークフロー | エージェント |
| 制御 | 手順をコードで固定（チェーン、ルーティング、並列化） | モデルが次の行動を決める（ツール使用ループ） |
| 向いているもの | 手順が決まっていて、再現性・監査が必要 | 手順を事前に決められない、開かれたタスク |
| コストと予測可能性 | 低コストで予測しやすい | 高コストで変動しやすい |

めたん: まず、ワークフローとエージェントは、何が違いますの？
ずんだもん: 誰が制御するか、なのだ。ワークフローは、手順をコードで固定するのだ。チェーン、ルーティング、並列化なのだ。
めたん: エージェントは？
ずんだもん: モデルが、次の行動を決めるのだ。ツール使用ループで動くのだ。
めたん: どちらを選べばよろしいの？
ずんだもん: 手順が決まっていて、再現性や監査が必要なら、ワークフローなのだ。低コストで、予測しやすいのだ。
ずんだもん: 手順を事前に決められない、開かれたタスクなら、エージェントなのだ。ただし、高コストで変動しやすいのだ。
めたん: 決まった手順なのに、自律エージェントを選ぶのは……
ずんだもん: 典型的なひっかけなのだ。決まった手順なら、ワークフローなのだ。

## SLIDE: スーパーバイザー階層とサブエージェント
- **マネージャー／スーパーバイザー階層**：オーケストレーターがタスクを分解し、ワーカー（サブエージェント）に割り当てる
- サブエージェントの役割：
- **コンテキストの分離**
- **専門化**（独自のシステムプロンプトやツール制限）
- **独立したタスクの並列化**

めたん: エージェントを、何人も使うこともできますの？
ずんだもん: できるのだ。マネージャー、スーパーバイザー階層なのだ。オーケストレーターがタスクを分解して、ワーカー、つまりサブエージェントに割り当てるのだ。
めたん: サブエージェントを使うと、何が嬉しいのかしら？
ずんだもん: 3つあるのだ。1つ目は、コンテキストの分離なのだ。
ずんだもん: 2つ目は専門化。独自のシステムプロンプトや、ツールの制限を持てるのだ。
ずんだもん: 3つ目は、独立したタスクの並列化なのだ。
めたん: 分離、専門化、並列化。覚えましたわ。

## SLIDE: 3-2 エージェントを作る4つの選択肢 ★
| 選択肢 | 誰が動かすか | 特徴（公式の Agent SDK 概要） |
| Agent SDK（Python/TS） | 自分のプロセス（セルフホスト） | Claude Code のエージェントをライブラリとして組み込む。組み込みツール、権限、セッション、フック、サブエージェント、MCP |
| Claude Code CLI | 開発者の端末 | 対話的な開発や単発のタスク。-p でヘッドレス実行 |
| Client SDK | 自分のコード | API に直接アクセス。ツールループは自作（または β の tool runner） |
| Managed Agents | Anthropic がホスト | ホスト型のハーネス。Anthropic 管理のクラウドサンドボックスか、セルフホストのサンドボックス。2026年11月時点ではベータ |

めたん: 3-2、エージェントの構築ですわ。
ずんだもん: 作り方は、4つの選択肢があるのだ。まず、{Agent SDK|エージェント エスディーケー}。
ずんだもん: 自分のプロセスで動かす、セルフホストなのだ。{Claude Code|クロードコード}のエージェントを、ライブラリとして組み込めるのだ。
めたん: 何が付いてきますの？
ずんだもん: 組み込みツール、権限、セッション、フック、サブエージェント、{MCP|エムシーピー}なのだ。
めたん: 2つ目は？
ずんだもん: {Claude Code|クロードコード}の{CLI|シーエルアイ}なのだ。開発者の端末で、対話的な開発や単発のタスクに使うのだ。{-p|ハイフン ピー}を付けると、ヘッドレス実行なのだ。
めたん: 3つ目は、{Client SDK|クライアント エスディーケー}ですわね。
ずんだもん: そうなのだ。{API|エーピーアイ}に直接アクセスするのだ。ツールループは、自分で作るのだ。ベータの{tool runner|ツールランナー}もあるのだ。
めたん: 最後の{Managed Agents|マネージド エージェンツ}は？
ずんだもん: {Anthropic|アンソロピック}がホストするハーネスなのだ。2026年11月時点では、ベータなのだ。

## SLIDE: 決定論的なアクションのためのフック ★
- **PreToolUse**：ツール実行前に **阻止・修正**
- **PostToolUse**：ツール実行後の **後処理**
- **プロンプトの指示は確率的、フックは確実に実行される**
```
async def protect_env(input_data, tool_use_id, context):
    if input_data["tool_input"].get("file_path", "").endswith(".env"):
        return {"hookSpecificOutput": {"hookEventName": input_data["hook_event_name"],
                "permissionDecision": "deny", "permissionDecisionReason": "no .env"}}
    return {}
options = ClaudeAgentOptions(hooks={"PreToolUse": [HookMatcher(matcher="Write|Edit", hooks=[protect_env])]})
```

めたん: エージェントが、してはいけないことをしそうなときは？
ずんだもん: フックを使うのだ。{PreToolUse|プレツールユース}は、ツールを実行する前に、阻止したり修正したりできるのだ。
ずんだもん: {PostToolUse|ポストツールユース}は、実行した後の後処理なのだ。
めたん: プロンプトに「しないでください」と書くのでは、だめですの？
ずんだもん: プロンプトの指示は、確率的なのだ。フックは、確実に実行されるのだ。
めたん: 確実に止めたいなら、フックですわね。
ずんだもん: このコードは、{Agent SDK|エージェント エスディーケー}で、{.env|ドットエンブ}ファイルへの書き込みを{PreToolUse|プレツールユース}フックで拒否する例なのだ。
ずんだもん: {Write|ライト}か{Edit|エディット}のときに呼ばれて、パスが{.env|ドットエンブ}で終わっていたら、{deny|デナイ}を返すのだ。

## SLIDE: 3-3 エージェントのパターンとフレームワーク（4.9%）
- パターン：**ツール使用ループ**、**サブエージェント**、**メモリ**、**コンテキストウィンドウの管理**
- 抽象化フレームワーク（試験ガイドの例）：**Strands**、**LangGraph**、**PydanticAI**
- トレードオフ：素早く作れる反面、**内部で何が起きているかが見えにくい**（デバッグや制御が難しくなる）
- 各フレームワークの細かい API は出題範囲として要確認 → **深追いしない**

めたん: 3-3は、パターンとフレームワークですわ。
ずんだもん: パターンは、ツール使用ループ、サブエージェント、メモリ、コンテキストウィンドウの管理なのだ。
めたん: フレームワークは、どんなものが出てきますの？
ずんだもん: 試験ガイドの例は、{Strands|ストランズ}、{LangGraph|ラングラフ}、{PydanticAI|パイダンティック エーアイ}なのだ。
めたん: 使うと、便利になりますの？
ずんだもん: 素早く作れる反面、内部で何が起きているかが見えにくくなるのだ。デバッグや制御が難しくなる、というトレードオフなのだ。
めたん: 細かい使い方まで覚える必要は？
ずんだもん: 各フレームワークの細かい{API|エーピーアイ}は、出題範囲として要確認なのだ。だから、深追いしないのだ。

## SLIDE: まとめ（分野1）
- 決まった手順なら **ワークフロー**、事前に決められない開かれたタスクなら **エージェント**
- サブエージェント：**分離・専門化・並列化**。独自のコンテキストで動き **要約を返す**、利用量は計上される
- 選択肢：**Agent SDK**（セルフホスト）／**Claude Code CLI**（-p でヘッドレス）／**Client SDK**（ループ自作）／**Managed Agents**（ベータ）
- 確実に止めるなら **PreToolUse フック**（プロンプトは確率的）
- フレームワークは **速さと見えにくさのトレードオフ**
