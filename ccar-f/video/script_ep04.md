## SLIDE: 3.1 CLAUDE.md の階層 ★
| スコープ | 場所 | 共有範囲 | 主な用途 |
| ユーザーレベル | ~/.claude/CLAUDE.md | 自分だけ（全プロジェクト）。VCS で共有されない | 個人の好み |
| プロジェクトレベル | ./CLAUDE.md または ./.claude/CLAUDE.md | チーム（コミットして共有） | アーキテクチャ、規約、共通ワークフロー |
| ディレクトリレベル | サブディレクトリの CLAUDE.md | そのディレクトリで作業する人 | その領域固有の規約 |
| （参考）ローカル | ./CLAUDE.local.md | 自分だけ（.gitignore 推奨） | 個人のサンドボックスURL等 |
| （参考）管理ポリシー | /etc/claude-code/CLAUDE.md 等 | 組織全員 | 全社規約（IT配布） |

めたん: まずは、{CLAUDE.md|クロード ドット エムディー}の階層ですわ。
ずんだもん: ユーザーレベルは、ホームの{.claude|ドット クロード}フォルダの{CLAUDE.md|クロード ドット エムディー}なのだ。自分だけで、全プロジェクトに効くのだ。バージョン管理では共有されないのだ。
めたん: チームで共有したいときは？
ずんだもん: プロジェクトレベルなのだ。リポジトリ直下の{CLAUDE.md|クロード ドット エムディー}か、{.claude|ドット クロード}フォルダの中に置いて、コミットするのだ。
ずんだもん: サブディレクトリに置けば、ディレクトリレベル。その領域固有の規約なのだ。
めたん: 参考の2つは？
ずんだもん: {CLAUDE.local.md|クロード ドット ローカル ドット エムディー}は自分だけで、ギットイグノア推奨なのだ。管理ポリシーは、{IT|アイティー}部門が配布する、組織全員向けの規約なのだ。

## SLIDE: CLAUDE.md の読み込み方（現行ドキュメント）
- 作業ディレクトリ **より上** の CLAUDE.md／CLAUDE.local.md は **起動時** に読み込み
- **サブディレクトリ** の CLAUDE.md は、そこのファイルを読む／編集するときに **オンデマンド**
- 見つかったファイルは上書きではなく **連結**（ルート側が先）
- **@path/to/file** でインポート（相対パスはインポート元基準、**最大4ホップ**）。整理には役立つが **コンテキスト量は減らない**
- 1ファイル **200行未満** が目安。**/compact 後もルートの CLAUDE.md は再読込**（会話だけの指示は消え得る）

めたん: 読み込まれるタイミングは？
ずんだもん: 作業ディレクトリより上にあるものは、起動時に読み込まれるのだ。
ずんだもん: サブディレクトリのものは、そこのファイルを読んだり編集したりするときに、オンデマンドで読み込まれるのだ。
めたん: 複数見つかったら、どれか1つが勝ちますの？
ずんだもん: 上書きではなく、連結なのだ。ルート側が先で、作業ディレクトリに近いものが後なのだ。
めたん: アットマークのインポートは？
ずんだもん: アット、パスで、ほかのファイルを取り込めるのだ。再帰は最大4ホップなのだ。ただし、整理には役立つけど、コンテキストの量は減らないのだ。
ずんだもん: それから、{/compact|スラッシュ コンパクト}の後でも、ルートの{CLAUDE.md|クロード ドット エムディー}は読み直されるのだ。会話だけで伝えた指示は、消えることがあるのだ。

## SLIDE: 3.1 の頻出ポイント／ひっかけ
- ○ 新メンバーに指示が効かない → 指示が **ユーザーレベル** にある → **プロジェクトレベルに移してコミット**
- ○ **/memory** で読み込まれているメモリファイルを確認し、挙動の不一致を診断
- ○ 巨大な CLAUDE.md は **.claude/rules/** のトピック別ファイルへ分割。パッケージごとに必要な規約だけ **@import**
- × 規約を **.claude/settings.json** に書く（settings は権限・フック・env 等）
- × 共有したい規約を **CLAUDE.local.md** に置く

めたん: 頻出のパターンは？
ずんだもん: 新しいメンバーにだけ、指示が効かない。原因は、指示がユーザーレベルにあることなのだ。プロジェクトレベルに移して、コミットするのだ。
めたん: 確認は、どうしますの？
ずんだもん: {/memory|スラッシュ メモリー}で、読み込まれているメモリファイルを確認するのだ。
めたん: {CLAUDE.md|クロード ドット エムディー}が大きくなりすぎたら？
ずんだもん: {.claude/rules|ドット クロード ルールズ}に、テスト、{API|エーピーアイ}規約、デプロイのように、トピック別に分けるのだ。パッケージごとに必要な規約だけを、インポートするのもいいのだ。
めたん: 規約を{settings.json|セッティングズ ドット ジェイソン}に書くのは？
ずんだもん: 間違いなのだ。{settings|セッティングズ}は、権限やフック、環境変数の設定なのだ。共有したい規約を{CLAUDE.local.md|クロード ドット ローカル ドット エムディー}に置くのも、間違いなのだ。

## SLIDE: 3.2 カスタムスラッシュコマンドとスキル
| 種類 | プロジェクト（チーム共有・VCS） | ユーザー（個人） |
| スラッシュコマンド | .claude/commands/<name>.md → /name | ~/.claude/commands/ |
| スキル | .claude/skills/<name>/SKILL.md | ~/.claude/skills/<name>/SKILL.md |

- ○ 全員がクローン／プルした時点で使える /review → **.claude/commands/**（サンプル問題4）
- × ~/.claude/commands/（個人用）／CLAUDE.md（コマンド定義の場所ではない）／.claude/config.json の commands 配列（**存在しない**）

めたん: 次は、カスタムスラッシュコマンドとスキルですわ。
ずんだもん: チームで共有するなら、プロジェクトの{.claude|ドット クロード}フォルダの中なのだ。コマンドは{commands|コマンズ}フォルダ、スキルは{skills|スキルズ}フォルダの中に{SKILL.md|スキル ドット エムディー}なのだ。
めたん: 個人用は、ホームの{.claude|ドット クロード}ですわね。
ずんだもん: そうなのだ。サンプル問題4は、全員がクローンやプルした時点で使える、スラッシュレビューを作りたい、という問題なのだ。
めたん: 答えは、{.claude/commands|ドット クロード コマンズ}ですわね。
ずんだもん: 正解なのだ。ホームのコマンズは個人用。{CLAUDE.md|クロード ドット エムディー}は、コマンドを定義する場所ではないのだ。
ずんだもん: そして、{config.json|コンフィグ ドット ジェイソン}のコマンズ配列は、そもそも存在しないのだ。存在しない機能が、選択肢に紛れ込むのだ。

## SLIDE: SKILL.md のフロントマター ★
| フィールド | 意味（試験ガイド） | 補足（現行ドキュメント） |
| context: fork | 分離されたサブエージェントのコンテキストで実行。出力がメイン会話を汚さない | サブエージェントは会話履歴を見ない（指示は自己完結に） |
| allowed-tools | スキル実行中のツールアクセスを制限 | 現行は事前承認。除外は disallowed-tools |
| argument-hint | 引数なしで呼ばれたとき必須パラメータの入力を促す | オートコンプリートのヒント。本文では $ARGUMENTS |
| （参考）description | — | Claude がいつ使うか判断する材料 |
| （参考）disable-model-invocation | — | 自動起動を禁止し、/name の手動起動だけに |

めたん: スキルのフロントマターで、試験に出るものは？
ずんだもん: 3つなのだ。1つ目は{context: fork|コンテキスト フォーク}。分離されたサブエージェントのコンテキストで実行して、出力がメインの会話を汚さないのだ。
めたん: サブエージェントで動くということは、会話履歴は見えませんのね。
ずんだもん: そうなのだ。だから、スキルの指示は自己完結に書くのだ。
ずんだもん: 2つ目は{allowed-tools|アラウドツールズ}。ガイドでは、ツールアクセスを制限する設定なのだ。前の回でやった、新旧のズレがある項目なのだ。
ずんだもん: 3つ目は{argument-hint|アーギュメント ヒント}。引数なしで呼ばれたときに、必須のパラメータの入力を促すのだ。
めたん: 参考の2つも、教えてくださる？
ずんだもん: {description|ディスクリプション}は、{Claude|クロード}がいつ使うかを判断する材料なのだ。{disable-model-invocation|ディセーブル モデル インボケーション}を{true|トゥルー}にすると、自動起動をやめて、手動起動だけにできるのだ。

## SLIDE: スキルの例と使い分け
```
---
name: analyze-deps
description: 依存関係を全体調査し、要約だけ返す
context: fork
argument-hint: [package-name]
allowed-tools: Read Grep Glob
---
$ARGUMENTS の依存関係を調べ、循環依存と未使用依存を表で要約する。
```
- ○ 冗長・探索的な出力 → **context: fork**／個人用は **~/.claude/skills/ に別名で**
- ○ **スキル＝オンデマンド**（タスク固有） vs **CLAUDE.md＝常時読み込み**（全体共通）

ずんだもん: 例はこんな感じなのだ。依存関係を調べて、要約だけを返すスキルなのだ。
めたん: {context: fork|コンテキスト フォーク}が付いていますわね。
ずんだもん: コードベースの分析みたいに冗長な出力や、代替案のブレストみたいな探索的な出力は、フォークで分離するのだ。
めたん: チームのスキルを、自分好みに変えたいときは？
ずんだもん: ホームのスキルズに、別の名前で作るのだ。チームのスキルを上書きしないのだ。
めたん: スキルと{CLAUDE.md|クロード ドット エムディー}の違いは？
ずんだもん: スキルは、必要なときに呼ぶ、タスク固有のワークフローなのだ。{CLAUDE.md|クロード ドット エムディー}は、常に読み込まれる、全体共通の標準なのだ。

## SLIDE: 3.3 パス固有のルール（.claude/rules/）
```
---
paths:
  - "**/*.test.tsx"
  - "**/*.test.ts"
---
# テスト規約
- describe/it は日本語で振る舞いを書く
- 外部APIは必ず msw でモックする
```
- **paths** の glob に一致するファイルを扱うときだけ読み込み（トークン節約）
- paths なしは **起動時に常に** 読み込み。フロントマターで読まれるのは **paths のみ**

めたん: 次は、パス固有のルールですわ。
ずんだもん: {.claude/rules|ドット クロード ルールズ}フォルダのマークダウンに、ヤムルのフロントマターで{paths|パス}を書くのだ。グロブパターンなのだ。
めたん: このルールは、いつ読み込まれますの？
ずんだもん: 一致するファイルを扱うときだけなのだ。だからトークンの節約になって、関係のない指示も入らないのだ。
めたん: {paths|パス}がないルールは？
ずんだもん: 起動時に、常に読み込まれるのだ。ちなみに、ルールのフロントマターで読まれるのは、{paths|パス}だけなのだ。

## SLIDE: どこに置く？（サンプル問題6）★
| 要件 | 最適解 |
| 規約がディレクトリをまたいで散在するファイル種別に適用（テスト、*.tf） | .claude/rules/ ＋ paths glob |
| 1つのディレクトリ配下だけの規約 | サブディレクトリ CLAUDE.md でも可（散在ファイルには不向き） |
| 全員・常時に効く標準 | プロジェクト CLAUDE.md |
| 必要なときに呼ぶ手順 | スキル／コマンド |

めたん: 似た選択肢が多くて、迷いそうですわ。
ずんだもん: 表で整理するのだ。テストファイルや、テラフォームのファイルみたいに、ディレクトリをまたいで散らばっているファイル種別なら、ルールズとパスのグロブなのだ。
めたん: 1つのディレクトリの中だけなら？
ずんだもん: サブディレクトリの{CLAUDE.md|クロード ドット エムディー}でもいいのだ。でも、散らばったファイルには向かないのだ。
ずんだもん: 全員に常に効かせたい標準は、プロジェクトの{CLAUDE.md|クロード ドット エムディー}。必要なときに呼ぶ手順は、スキルかコマンドなのだ。
めたん: サンプル問題6の誤答は？
ずんだもん: ルートの{CLAUDE.md|クロード ドット エムディー}に見出しで集めるのは、推測任せなのだ。スキルにするのは、手動呼び出しに頼ることになるのだ。
ずんだもん: 各サブディレクトリに置くのは、散在するファイルに向かないのだ。

## SLIDE: 確認クイズ：どこに置く？（オリジナル）

めたん: では、確認クイズですわ。規約がシニアエンジニアのホームの{CLAUDE.md|クロード ドット エムディー}にあって、新メンバーに効かない。
ずんだもん: プロジェクトの{CLAUDE.md|クロード ドット エムディー}に移してコミット。{/memory|スラッシュ メモリー}で確認するのだ。
めたん: あちこちに散らばったテラフォームのファイルの規約を、編集するときだけ読ませたい。
ずんだもん: ルールズにテラフォーム ドット エムディーを作って、{paths|パス}に、アスタリスク2つ、スラッシュ、アスタリスク ドット ティーエフなのだ。
めたん: 依存関係のスキルの中間出力で、メインの会話が埋まってしまう。
