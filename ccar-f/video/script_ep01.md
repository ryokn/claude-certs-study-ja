## SLIDE: ズレ（3）スキルの allowed-tools ★
| | 試験ガイド | 現行ドキュメント |
| allowed-tools の意味 | スキル実行中のツールアクセスを 制限 する | 呼び出したターンの間、列挙したツールを 許可プロンプトなしで使える（事前承認）。他のツールを使えなくするわけではない |
| 除外したいとき | — | disallowed-tools |
| 試験での扱い | ガイドの文脈（スキル用にツールを絞る設定）で解く | 実務では disallowed-tools や権限設定も併用 |

ずんだもん: ここは、意味そのものが違うので要注意なのだ。
ずんだもん: 試験ガイドでは、スキル実行中のツールアクセスを制限する設定、と説明されているのだ。
めたん: 今のドキュメントでは？
ずんだもん: 呼び出したターンの間、列挙したツールを、許可プロンプトなしで使えるようにする、事前承認なのだ。ほかのツールを使えなくするわけではないのだ。
めたん: 除外したいときは？
ずんだもん: {disallowed-tools|ディスアラウドツールズ}なのだ。でも試験では、ガイドの文脈、つまりスキル用にツールを絞る設定として解くのだ。

## SLIDE: ズレ（4）MCP のスコープ
| | 試験ガイド | 現行ドキュメント |
| スコープ | project（.mcp.json）と user（~/.claude.json）の2つ | local（既定）／ project ／ user の3つ |
| 保存先 | — | local と user はどちらも ~/.claude.json |
| 同名定義の優先順位 | — | local ＞ project ＞ user |
| 試験での扱い | ガイドの2分類で解けばよい | |

めたん: {MCP|エムシーピー}サーバーのスコープは、どうですの？
ずんだもん: ガイドでは2つなのだ。プロジェクトスコープの{.mcp.json|ドット エムシーピー ドット ジェイソン}と、ユーザースコープの{~/.claude.json|ホーム ドット クロード ドット ジェイソン}なのだ。
ずんだもん: 今のドキュメントでは3つなのだ。既定のローカル、プロジェクト、ユーザーなのだ。
めたん: ローカルは、どこに保存されますの？
ずんだもん: ローカルとユーザーは、どちらも{~/.claude.json|ホーム ドット クロード ドット ジェイソン}に保存されるのだ。同じ名前の定義があれば、ローカル、プロジェクト、ユーザーの順で優先されるのだ。
めたん: 試験では？
ずんだもん: ガイドの2分類で解けばいいのだ。チーム共有はプロジェクト、個人用はユーザーなのだ。

## SLIDE: ズレ（5）tool_choice と構造化出力
| トピック | 試験ガイド | 現行ドキュメント |
| 強制ツール選択 | "any" と {"type":"tool","name":...} | 手動の拡張思考や一部の最新モデルでは any／tool が非対応（400エラー）。代替は auto＋strict tool use か structured outputs |
| 構造化出力 | tool_use＋JSONスキーマ、strict モード | ツール入力の strict: true と、応答本体の JSON outputs（output_config.format）の2本立て |
| 試験での扱い | any＝いずれかのツールを必ず、tool＝指定ツールを必ず／tool_use＋スキーマが最も信頼性が高い | |

めたん: {tool_choice|ツールチョイス}にも、ズレがありますのね。
ずんだもん: ガイドでは、{any|エニー}と、ツール名を指定する強制選択が出てくるのだ。
ずんだもん: 今のドキュメントでは、手動の拡張思考や、一部の最新モデルでは、{any|エニー}や指定ツールの強制が使えず、400エラーになるのだ。
めたん: そのときの代わりは？
ずんだもん: {auto|オート}に{strict tool use|ストリクト ツールユース}を組み合わせるか、{structured outputs|ストラクチャード アウトプッツ}なのだ。
めたん: 構造化出力も、変わりましたの？
ずんだもん: ガイドは、ツールユースと{JSON|ジェイソン}スキーマ、それに{strict|ストリクト}モードなのだ。今は、ツール入力の{strict|ストリクト} {true|トゥルー}と、応答本体の{JSON outputs|ジェイソン アウトプッツ}の2本立てなのだ。
ずんだもん: 試験はガイド通りなのだ。{any|エニー}はどれかのツールを必ず、指定ならそのツールを必ず。そして、ツールユースとスキーマが、最も信頼性が高いのだ。
