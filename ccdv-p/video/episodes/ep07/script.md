## SLIDE: 第1章　worktreeで並列に分離する
@code_label: 並列セッションの起動
@diagram: flow | 衝突を避ける
@node: worktreeを作成して起動
@node: 各セッションが別ブランチで作業
@node: 小さく頻繁にマージ
@node: マージ後に全体テスト
```bash
claude --worktree feature-a
# または -w feature-a

# 作られる場所:
# .claude/worktrees/feature-a/
# ブランチ: worktree-feature-a
```
[L] めたん: 今回は、エージェントのフリート運用ですわね。
[L] ずんだもん: フリートは、複数のコーディングエージェントを、同時に動かす運用なのだ。
[L] ずんだもん: まず、worktreeで分離するのだ。
[R] ずんだもん: 右の流れ図のとおり、各セッションが別のブランチで作業するので、変更が衝突しないのだ。
[L] めたん: 左のコマンドで、専用の作業ツリーとブランチが作られますのね。
[L] ずんだもん: worktreeは新しいチェックアウトなので、依存関係のインストールや、環境ファイルの持ち込みが必要なのだ。

## SLIDE: 第3章　ヘッドレス実行
@code_label: claude -p の使い方
@diagram: table | オプションと役割
@size: 26
@cols: 役割
@row: -p | 指示を渡して非対話で実行
@row: --allowedTools | 自動承認するツールを限定
@row: --output-format | 構造化出力にする
@row: --bare | 自動検出を省く
```bash

  --allowedTools "Bash,Edit" \
  --output-format json \
  --bare
```
[L] めたん: スクリプトから呼ぶときは、どうしますの？
[L] ずんだもん: 左のように、claude -pで実行するのだ。
[L] ずんだもん: 右の表のとおり、自動承認するツールは、allowedToolsで限定するのだ。
[R] めたん: bareは、何をするのですの？
[R] ずんだもん: hooksやskills、MCP、CLAUDE.mdなどの自動検出を省くのだ。
[R] ずんだもん: スクリプトやSDKからの呼び出しに、推奨されているのだ。
[L] ずんだもん: 出力形式は、構造化にしておくと、後続の処理で扱いやすいのだ。

## SLIDE: 第3章　bareなしの注意
@code_label: 信頼確認の落とし穴
@diagram: ba | -p の挙動
@before: bareあり | 自動検出\nを省く

@result: 信頼していないリポジトリでの無人実行は要注意
```text

  .claude/settings.json の
  フック
  .mcp.json のサーバー

```

[R] めたん: 信頼していないリポジトリで、無人実行するのは危険ですのね。
[L] ずんだもん: リポジトリ側に仕込まれたフックが、そのまま実行されうるからなのだ。
