## SLIDE: 第1章　ガードレールは多層で考える
@code_label: 層ごとの性質
@diagram: table | 層と強制力
@size: 26
@cols: 性質
@row: 入力 | 確率的・要調整

```text
入力 → モデル →

プロンプトだけに頼らず

```

[R] めたん: システムプロンプトには、強制力がないのですわね。
[L] ずんだもん: ツール実行の前と、実行環境が、決定的な層なのだ。左の流れで、層を重ねるのだ。

## SLIDE: 第1章　取り消せない操作を止める
@code_label: PreToolUseのフック（概念）
@diagram: flow | 実行前の関門
@node: エージェントがツール呼び出しを要求
@node: PreToolUseフックが検査
@node: 許可・承認ゲート・拒否
@node: 通ったものだけ実行
```python
# 削除は人の承認なしに
# 通さない（オリジナル例）
def pre_tool_use(call):
    if call.name == "delete_db":
        return deny("承認が必要")
    return allow()
```
[L] めたん: 削除や送金は、どう止めますの？
[L] ずんだもん: ツール実行の前に、フックで止めるのだ。
[L] ずんだもん: PreToolUseは、ツール実行前に走って、ブロックできるのだ。
[R] ずんだもん: 右の流れ図が関門なのだ。検査して、許可、承認ゲート、拒否に振り分けるのだ。
[L] めたん: 左のコードは、削除ツールを、承認なしには通さないのですわね。
[L] ずんだもん: モデルに、慎重にと頼むのは、ガードレールではないのだ。決定的な検査が要るのだ。
